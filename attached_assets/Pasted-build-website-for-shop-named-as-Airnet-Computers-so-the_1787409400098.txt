5. Basic algorithm for the complete system
A. Adding a customer
START

User opens Add Customer form

        ↓

User enters customer information

        ↓

Frontend validates form

        ↓

Send POST request to backend

        ↓

Backend validates again

        ↓

Check duplicate mobile number

        ↓

Generate unique Customer ID

        ↓

Save customer in PostgreSQL

        ↓

Create audit log

        ↓

Emit real-time event

        ↓

All connected computers receive update

        ↓

Refresh customer list automatically

END
Pseudo algorithm:
function createCustomer(data, user) {

    validate(data)

    duplicate = findCustomerByMobile(data.mobile)

    if (duplicate) {
        return error("Customer already exists")
    }

    customerId = generateUniqueId()

    customer = database.insert({
        customerId,
        ...data,
        createdBy: user.id
    })

    createAuditLog({
        user: user.id,
        action: "CREATE_CUSTOMER",
        record: customer.id
    })

    socket.broadcast("customer:created", customer)

    return customer
}

7. Advanced conflict handling
Suppose:
Computer A edits Customer Name
AND
Computer B edits Customer Mobile Number
at almost the same time.
The backend should handle this carefully.
Use:
updated_at
version_number
transaction
optimistic locking
Example:
Customer Version = 15

Computer A loads Version 15
Computer B loads Version 15

Computer A saves
→ Version becomes 16

Computer B tries to save Version 15

Backend detects mismatch

→ Return conflict
→ Reload latest data
→ Ask user to review changes
Algorithm:
IF incoming_version == database_version
    UPDATE record
    version = version + 1
ELSE
    RETURN "DATA_CHANGED_BY_ANOTHER_USER"
This prevents one computer from silently overwriting another computer's changes.
